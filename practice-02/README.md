## Распределение ответственности между файлами

- `src/data.js` — хранит общий набор демонстрационных задач `demoTasks`. Никаких функций изменения или вывода здесь нет.
- `src/task-service.js` — девять прикладных функций: `createTask`, `findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`, `addTask`, `setTaskCompleted`, `renameTask`, `removeTask`. Модуль не знает про конкретный массив, не выводит в консоль и не хранит глобального состояния.
- `src/main.js` — общий сценарий: импортирует данные и функции, последовательно применяет операции, ведёт текущее состояние `currentTasks` и обрабатывает отказы.
- `checks.js` — автономные проверки через `node:assert/strict`, не изменяют входные данные и не подменяют результат заранее записанными сообщениями.

## Общий сценарий main.js

Фактический вывод после `npm.cmd start`:

- Исходная сводка: Всего 4, выполнено 2, осталось 2, прогресс 50.0%.
- После добавления id = 20: Всего 5, выполнено 2, осталось 3, прогресс 40.0%.
- После установки completed = true для id = 4: Всего 5, выполнено 3, осталось 2, прогресс 60.0%.
- После переименования id = 10: Всего 5, выполнено 3, осталось 2, прогресс 60.0%.
- После удаления id = 7: Всего 4, выполнено 3, осталось 1, прогресс 75.0%.

Итоговые идентификаторы: [1, 4, 10, 20]. Единственная незавершённая задача: id = 20.

Показан отказ на повторное добавление id = 20: «Задача с таким id уже существует». Идентификаторы после отказа не изменились.

## Протокол общих проверок

Команда `npm.cmd run check` завершилась без ошибок: `Пройдено: 66, провалено: 0`.

Общие проверки покрывают:

- createTask: обычные значения, приоритет по умолчанию и undefined, trim, границы длины 1 и 100, пустая строка, длина 101, нестроковые title, невалидные id (0, −1, 1.5, строка, NaN, Infinity, null, undefined, MAX_SAFE_INTEGER + 1), допустимый MAX_SAFE_INTEGER, невалидные приоритеты (urgent, HIGH, « high », null, число), два вызова создают разные объекты.
- findTaskById: id = 4, отсутствующий id, строка «4», пустой массив.
- getPendingTasks: общий набор, пустой массив, всё выполнено, ничего не выполнено.
- getTaskTitles: общий набор, пустой массив.
- getTaskStats: общий набор, пустой массив, 0%, 100%, 1 из 3 (~33.33).
- addTask: id = 20, пустой массив, повтор id = 4, некорректный title, некорректный id.
- setTaskCompleted: id = 4 → true, остальные поля сохраняются, отклонение «true», 1, null, undefined, задача не найдена, новый объект задачи.
- renameTask: id = 10 с пробелами, пустая строка, число, задача не найдена, исходный массив не изменён, повтор текущего названия — успех.
- removeTask: id = 7, единственная задача, задача не найдена, пустой массив.

## Собственные проверки

Добавлены в `checks.js` после общих. Три случая отличаются от общих исходными данными и последовательностью действий.

| Проверка | Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|---|

| Изменение первой и последней записи | setTaskCompleted для id = 1 (true → false) и id = 10 (true → false) | Обе операции успешны, поле completed меняется только у выбранной записи | Обе операции успешны, остальные поля сохранены | Пройдено |
| Последовательное обновление нескольких задач | renameTask для id = 1, затем для id = 10, затем setTaskCompleted для id = 4 | Каждая операция работает с результатом предыдущей, исходный список не изменяется | Все три операции успешны, порядок id сохраняется | Пройдено |
